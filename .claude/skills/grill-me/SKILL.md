# Grill me(拷問)

改寫自 [mattpocock/skills](https://github.com/mattpocock/skills) 的 `grilling`(MIT License, Copyright (c) Matt Pocock),加上 hanmask 的前提檢查。

窮追猛問，直到和使用者對這件事有共同理解。把它畫成**決策樹**:每個決策底下會長出依賴它的決策。

## 先找前提錯誤

每個決策先問「為什麼要這樣」,再對照實際環境(`docs/work-mode.md`「環境」:cat 開發、dog 跑 proxy)。常見來源:
- 沿用慣例或範本，沒對照 hanmask 實際情況(例：dog 只從 tag 安裝、不 commit;repo 是公開的)
- 解決一個不存在或已被既有機制涵蓋的問題(先 grep 有沒有現成的)
- 每台各自的狀態(gitignored 檔、`local/`、本機 memory)被當成跨機器共用

## hanmask 的五種失效

每個改到辨識或 proxy 的決策，逐一問：

1. **漏遮**:真實文字的寫法(全形、無空白、換行、標籤在值後面、英文標籤)會不會繞過規則?合成句型是不是只照規則寫、量測才會 100%?
2. **誤遮**:訂單編號、金額、版本號、日期會不會被當成個資?遮了會不會讓 LLM 失去完成任務需要的資訊?
3. **還原失敗**:佔位符被 LLM 改寫(`<PHONE 1>`、`PHONE_1`、翻譯成中文)、重複、出現在 JSON 字串或 tool call 參數裡時，還原得回來嗎?
4. **串流切斷**:佔位符被切在兩個 SSE 片段之間、或串流中途斷線時，會不會吐出半個佔位符或把原文卡住?
5. **tool_result 未遮**:Claude Code 讀檔、跑指令的結果(`tool_result`)、system prompt、圖片與 PDF 有沒有走同一條遮蔽路徑?

## 分輪提問

**前線** = 前提都已定案、現在就能問而不必猜答案的決策。每輪把整個前線一次問完：每題編號、附上推薦答案，然後等使用者回答再進下一輪。

格式:

```
❓ **Q1** - **<題目>**:<內容，可多段、可含選項>

➡️ <推薦答案>

---

❓ **Q2** - **<題目>**:<內容>

➡️ <推薦答案>
```

- 題目措辭要讓「是」= 接受推薦答案。
- 推薦答案來自專業判斷，不因「改動最少」就推維持現狀。
- 使用者每輪的回答會改變決策樹：已定案的往外推、解鎖下游問題；重算前線再問下一輪。答案取決於本輪另一題的問題，留到下一輪。

## 事實自己查，決策交給使用者

- 需要環境事實(檔案、設定、git、工具、跑一次 `Masker().mask(...)`)→ 自己查或派子 agent,不問使用者。查詢進行中只擋住它下游的問題，其餘照問。
- 決策是使用者的：逐一提出、等回答。

## 結束

前線清空 = 決策樹每個分支都走過、沒有默默假設的東西。使用者確認達成共識前，不依此動手。
