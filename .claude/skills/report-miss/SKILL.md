# 回報問題(report-miss)

真實資料不能離開 dog,repo 是公開的。這個 skill 只產出**合成**內容，而且不替使用者送出:dog 上不登入 `gh`。

## 進度清單(複製到回覆逐項打勾)

```
- [ ] 1. 確認環境是 dog、問題類型
- [ ] 2. 改寫成合成資料
- [ ] 3. 寫會失敗的 pytest 並實跑
- [ ] 4. 產生 Issue 草稿
- [ ] 5. 掃描 + 自我檢查
- [ ] 6. 交給使用者
```

## 1. 確認環境與類型

- `CLAUDE.local.md` 寫的環境不是 dog → 停下問。cat 沒有真實資料，不該用這個 skill。
- 類型四選一：漏遮(該遮沒遮)/ 誤遮(不該遮卻遮了)/ 還原失敗 / 其他(擋下、錯誤)。
- 記下目前版本:`git describe --tags --always`。

## 2. 改寫成合成資料

目標：開發者在 cat 上用合成資料重現同一個問題，看不出原文是什麼。

- **保留**:格式與結構(全形 / 半形、空白、分隔符、換行)、標籤用語(`統編`、`訂單編號`)、值相對於標籤的位置、長度。
- **替換**:每一個值都換成合成值。有檢查碼的類型要產生**檢查碼正確**的假值(身分證、統編、信用卡;可用 `bench/synth.py` 的產生器),否則重現不了漏遮。
- **刪除**:公司名稱、人名、部門、客戶、產品、內部系統名、路徑、IP、網址、金額、日期;換成通用說法(「範例科技」「王小明」「某系統」)或直接刪掉與問題無關的句子。
- 只留重現問題需要的最短句子，不貼整段原文。

## 3. 寫會失敗的 pytest

寫在 `local/test_miss_<YYYYMMDD>_<主題>.py`(gitignored),期望「修好之後」的行為:

```python
from hanmask import Masker


def test_<主題>():
    masked, _ = Masker().mask("<合成句子>")
    assert masked == "<期望結果>"
```

實跑 `python -m pytest local/test_miss_<...>.py -q`,確認**失敗**而且失敗原因就是要回報的問題。沒失敗 → 合成資料沒重現問題，回第 2 步調整。

## 4. Issue 草稿

寫在 `local/issue-<YYYYMMDD>-<主題>.md`:

````markdown
<!-- title: [from-dog] <類型>:<一句話描述,不含任何原文> -->
<!-- label: from-dog -->

**類型**:漏遮 / 誤遮 / 還原失敗 / 其他
**版本**:<git describe 結果>

**合成輸入**
```
<合成句子>
```

**期望**:<期望結果>
**實際**:<目前結果>

**會失敗的測試**
```python
<第 3 步的測試>
```
````

## 5. 掃描 + 自我檢查

1. `python scripts/sensitive_scan.py --skip-pii local/issue-<...>.md` 須零命中(禁用字清單在 `local/guard-words.txt`;合成值檢查碼正確是刻意的，所以用 `--skip-pii`)。命中 → 回第 2 步，不貼命中內容到對話。
2. 逐條自問，任一條「是」就回第 2 步：
   - 有沒有任何一段文字是從原文複製的(除了標籤用語)?
   - 看得出是哪家公司、哪個部門、哪個客戶或哪個人嗎?
   - 有沒有路徑、主機名、IP、網址、內部代號?

## 6. 交給使用者

- 把草稿完整貼在回覆裡，附檔案路徑。
- 請使用者看過後：到 GitHub 開新 Issue、貼上內容、加 label `from-dog`。
- 不執行 `gh issue create`,不 commit、不 push。`local/` 的檔案由使用者決定何時刪除。
